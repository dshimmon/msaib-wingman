# Future Radar Attachment Note

This is a documentation-only boundary note. Mission 028 adds no Radar code,
schema, vocabulary, workflow, production registration, or selection path.

If Maverick later authorizes a separate Radar product mission, that product
must attach through Product Contract v1 or an explicitly approved later
version. Its product layer—not Core—would own its stable ID and display name,
record declarations and enrichment, source-metadata rules, retrieval
interpretation, reporting or Briefing capability, UI vocabulary, and defaults.

The product would be added to an explicit reviewed production registry only as
part of that future authorization. Shared composition would receive its
immutable Product Context and pass neutral callbacks, plans, schemas, values,
and opaque metadata to Core. Core must not gain product-ID branches or domain
terminology to support the attachment.

No future product may bypass source IDs, evidence, provenance, original-source
paths, human review, or the Ledger schema and migration gates.
