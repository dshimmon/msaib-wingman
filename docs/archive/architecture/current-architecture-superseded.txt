SQLite Ledger

Every Ledger connection configures:

* sqlite3.Row
* PRAGMA foreign_keys = ON
* PRAGMA journal_mode = WAL
* PRAGMA busy_timeout = 5000

Repository mutations require an active caller-owned
transaction.

Repositories do not independently commit.

Multi-row writes use savepoints so a caught specialized-row
failure cannot leave a partial shared entity.

CONVERSATION GUARDRAILS
=======================

Conversation history may be used to understand:

* Pronouns
* References
* Omitted subjects
* Follow-up scope
* Which prior entities the user means

Conversation history may not be used as:

* Supporting evidence
* A replacement for retrieval
* Proof that a prior answer was correct
* Permission to accept a false premise
* Authority over the current question

Core rule:

Conversation provides context.
Sources provide truth.

MISSION 026 PRINCIPLE
============================================================

Wingman services depend on storage contracts,
not storage files.


Deterministic persistence owns:

- Durable identity
- Metadata
- Relationships
- Versions
- Transactions
- Historical snapshots
- Migration state


Application services own:

- Product behavior
- Retrieval orchestration
- Briefing generation
- Library operations
- User-facing workflows


The storage implementation remains hidden behind
repository and service contracts.

============================================================
MISSION 026 OUTCOME
============================================================

Before Mission 026:

Source metadata was stored in a standalone JSON registry.

Generated briefings existed only in Streamlit session state.

System metadata was spread across unrelated files without
a shared transactional identity or version model.

- Shared entity identities
- Ordered schema migrations
- Caller-owned transactions
- Repository savepoints
- Ledger-backed source metadata

- One-time legacy-registry import
- Active and removed source states
- Immutable briefing versions

- Deterministic source fingerprints
- Action-storage foundations
- Diagnostic-event persistence
- Product-neutral repository contracts
